# AGENTS
- Clinical safety follows src/pages/health/AGENTS.md; admin decisions use verified identity and conditional writes in health-access/admin-decision.ts, sharing approval-email.ts to prevent mail drift.
- Expanded sample charts derive exclusively from existing numbered fictional transcripts; missing demographics, allergies, medicine reconciliation and results stay unknown, and source history contains only an undated fixture baseline rather than fabricated staff actions or a live clinical audit.
- Connected clinical doctor-day shares one validated fictional case across rehearsal slots, historical chart/transcript, existing clinic-scoped note decisions and unapproved follow-up guides; case changes reset navigation, illustrative slots never mark encounters complete, and note signatures never unlock booking or delivery.
- Clinical enterprise readiness is a shared informational drawer using the existing intake lock policy; fixed unverified legal/vendor/pilot statuses cannot approve, certify or activate services, so presentation never becomes a healthcare clearance mechanism.
- Clinical specialty examples share a read-only fixture screen across demo and clinic workspace, with exact transcript excerpts and case-local source selection; separate rehearsal sources never enter generated notes, signatures, exports or patient delivery.
- Clinical practice impact uses a shared local-only calculator with blank visitor-supplied assumptions and a pure validated calculation; modeled time-capacity value is never represented as measured savings, revenue or product pricing.
- Clinical prior-authorization preparation shares one fixed transcript packet across demo and workspace, validates exact source quotes, keeps review rehearsal unsaved, and has no signature, export or submission action; prevents fictional drafts from becoming insurer-ready claims.
- Clinical walkthrough and fixed voice share demo/workspace navigation; read-only sources and gate-scoped playback never generate, sign, send or execute agents. See health/AGENTS.md for voice boundaries.
- Clinical private access uses atomic server deadlines/device binding; expiry or exit consumes approval, and sign-out/reload stops media. The shared gate watermarks only the current verified viewer; details follow health/AGENTS.md.
- Clinical mail uses health-access/email-routing.ts for routing and confirmation.ts for shared inline brand tokens; approval-email.ts serves all invitations to prevent drift. Escape visitor fields, retain plain text and require a provider message ID before claiming sending acceptance.
- Public directory lookup functions (search_directory_businesses, get_directory_*) must stay executable by anon + authenticated; security revokes broke the directory Sep 26 2026.
- Hard Kayla chat questions (strategy/money/legal/forecast) go through `premiumChatAnswer` in `_shared/kayla-deep.ts` (premium draft + self-check) on every chat function; keeps quality consistent and fail-open to the fast model.
- Kayla web lookups live only in `_shared/kayla-grounding.ts` `webSearch` (Perplexity first, Firecrawl fallback); answers that used the web must end with a Sources list from returned URLs only.
- Voice Kayla (`realtime-token`) builds instructions from `buildKaylaSystemPrompt` + memory; only speaking style lives in that file, so voice and chat never drift.
- Approved weekly scoreboard fixes (`kayla_improvement_proposals`, status approved) are injected via `loadApprovedImprovements` in every Kayla channel; nothing applies without admin approval.
- Each Agentic AI Employee reads its own approved/rejected history via `agentLessons` in `_shared/kayla-agent-learning.ts`; team handoffs (max 2 per question) live only in `_shared/kayla-handoffs.ts` and are logged to `kayla_agent_handoffs`; per-employee test questions are `kayla_benchmark_cases.agent_name`. Keeps learning and teamwork in one place.
- Non-Black-owned "Ally" listings use `businesses.listing_type='ally'` and, once approved, `listing_status='ally_live'` (forced by a trigger, with is_verified false); every main-directory query filters `live`, so allies can never leak in. Allies are read only through `get_ally_businesses` (public, anon + authenticated).
- Listing approval reviewers coordinate through `listing_review_claims` (one claim per business, 10-minute expiry) and approve/reject updates filter on the current status; prevents two admins reviewing or approving the same listing.
- The MCP edge function is deployed manually with the Supabase CLI using the project secret SB_DEPLOY_TOKEN (edge-functions-only, expires ~Jan 2027); GitHub Actions workflow deploy-mcp.yml is a backup needing repo secret SUPABASE_ACCESS_TOKEN. Lovable cannot deploy it to this user-managed Supabase project.
- Clinical `hc_*` data uses approved clinic membership, private `hc-sample-docs` storage and fixed fictional sources; client clinical writes stay blocked until healthcare clearance.
- Subdirectories have their own AGENTS.md (clinical rules: src/pages/health/AGENTS.md); read them before changing files there.
