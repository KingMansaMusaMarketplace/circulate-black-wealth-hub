# 1325 Clinical rules
- Dashboard operations share independent fixed fictional queue, supply and KES collection scenarios across demo/workspace; SHA pending is excluded from received totals and browser status has no clinical cache, queue or sync, so operational presentation cannot imply live care or integrations.
- Public clinical photography uses explicit page-owned imports and optional image-bearing feature cards with illustrative captions, keeping placement auditable without changing private workflows.
- Clinical narration is fixed prerecorded explanation or numbered fictional evidence in one gate-scoped player, never a second prompt or agent execution; sound defaults off and gate unmount stops audio to preserve intake and private-session boundaries.
- Clinical server operations require validated Auth plus active email-matched owner approval/device/deadline, or server-verified admin access; data policies use the private checker and clients cannot write patient/chart/billing text. Product questions use a closed browser-local vocabulary and transmit only catalog topic/intent IDs; raw typing, microphone and patient input remain blocked, so warnings cannot substitute for intake restrictions.
- Clinical product conversation uses shared Kayla identity and server-owned documentation with signed user-bound history; gate-scoped memory clears on access/account loss, sends bounded verified context and discards failed turns. No persistence, general chat, specialist execution or clinical tools; opt-in answer speech shares one audio lane with narration.
- Saved note assertions and review findings are exact source excerpts, with AI grouping kept separate from correctness claims; one atomic decision per version prevents conflicting sign/reject outcomes. Typed signer names and team roles are sample attestations, not verified physician licensure.
- Clinical loaders return rows or failure, clear stale content and ignore obsolete requests; guarded mutations confirm saved identifiers before success. Exports validate every statement/flag against verbatim source excerpts; email decisions open a 1325.ai confirmation screen and change state only on a deliberate POST carrying the secret link token, conditional on current status, so scanners cannot decide and phones work.
- Clinical Data Explorer shares an independent numbered synthetic packet across demo/workspace with fixed question choices and validated threshold/unit/date criteria; edits invalidate confirmation/results, missing or out-of-window evidence remains unknown, and no network, persistence, chart merging, record import, export, recruitment or quality submission is permitted, so search rehearsal cannot become clinical clearance.
- Clinical safety is a shared read-only drawer using existing numbered fixtures, chart gaps, medication-review statuses and intake locks; case changes and closing reset source selection, with no screening, risk scoring, persisted decisions or clearance so advisory presentation cannot bypass physician review.
- Executive quality overview shares exact fictional source inventory and null performance results across demo/workspace; facility context is illustrative only, navigation cannot approve or export, and live restrictions derive from intake policy so sample evidence never becomes measured clinical quality or healthcare clearance.
- Facility selection is page-local fictional presentation shared by demo/workspace; IDs never enter clinic queries, permissions or saved records, and demo changes reset rehearsal state so hospital examples cannot imply live multi-facility access.
- Doctor evaluation shares existing fictional transcripts and blank structured local observations across demo/workspace; case changes clear observations, no free-text records, persistence, aggregate study claims or approval, and the intake lock keeps real pilots unavailable so rehearsal cannot imply clinical validation.
- Enterprise reliability shares fixed backup/recovery/migration requirements across demo/workspace through the intake lock policy, with unknown destinations, targets, test results and imports; no file inputs, execution, persistence or approval, so preparation never certifies infrastructure or activates patient transfers.
- Billing preparation shares fixed documentation evidence across demo/workspace; a separate labeled simulation studio shows fixed illustrative codes, simulated eligibility, claim preview and quality status for fictional visits only, with no transport, saving, export, collection or approval, so rehearsal never becomes coverage or reimbursement clearance.
- Patient communication reuses validated fictional transcripts and bilingual care-guide drafts without patient input, persistence or transport; excerpts are not received messages, relative follow-up intervals never become booked dates, and case changes reset language/source selection while consent, approval and all live communication remain unavailable.
- Clinical connection preparation shares fixed laboratory/pharmacy/record-exchange requirements and illustrative mappings across demo/workspace, using the intake lock policy without connector calls, credentials, patient input, imports or approval controls; prevents rehearsal mappings and agreements from appearing to activate live clinical exchange.
- Medication-review assistance uses exact sample-chart medicine quotations in a shared local read-only rehearsal; absent allergies stay unknown and future dose discussion stays uncompleted, with no prescribing, interaction screening, saved approval or delivery, so documentation gaps cannot become clinical safety clearance.
- Clinical record review uses server-owned fixtures, rejects client record text, validates exact page quotations before saving, and records separate clinic-authorized review decisions; this prevents uploads from bypassing the fictional-only stage and keeps AI completion distinct from physician review.
- Clinical pilot readiness stores fixed boolean attestations only, derives requester identity from validated Auth, and remains awaiting independent verification; neither clinic reports nor signed agreements enable real-record processing in the unapproved environment.
- The clinical BAA route is a read-only preparation page without signature submission or agreement storage until approved legal documents and vendor coverage exist; this prevents placeholder copy from becoming an executable contract.
- Clinical intake reuses existing authenticated clinic registration and membership reads; no BAA or CME file picker, storage destination or upload action exists in this environment, so readiness reports cannot bypass healthcare clearance.
- CME portal reuses clinic-scoped fictional documents, source-linked reviews and physician decisions; its shared access/status policy keeps upload availability separate from clinic membership and AI completion separate from doctor review.
- Clinical account setup validates sign-in before calling hc_create_clinic, reads back the returned clinic through current-user membership, and retains saved IDs for retry; account-keyed loading rejects stale results and avoids duplicate creation after readback failures.
- Registration seeds transcript-linked fictional identities only with missing facts unknown; retained legacy records are unverified and their unsupported details are not shown as clinical evidence. Team additions cannot demote an owner or creator, preventing accidental loss of clinic management.
- Saved review acceptance rechecks immutable packet identity, literal quotations, assertions and source dates; revision requests remain available for unsupported older drafts. Approval cookies are request/action-scoped and consumed after saved decisions so independent email tabs cannot overwrite one another.
- Clinical AI note-taking (health-kayla-notes) drafts only from server-owned fictional transcripts, cites transcript lines validated server-side, and stores doctor sign-off separately (hc_note_signoffs, one decision per note); live recording stays locked until HIPAA clearance. Clinical edge functions deploy via Supabase CLI with SB_DEPLOY_TOKEN.
- Clinical chart prep uses exact numbered fixture excerpts; chronology sorts immutable dated records with undated records last and validates flag quotes. Neither accepts chart text, invents current findings, promotes planned visits to completed events, or persists approval.
- Clinical care guides use fixed bilingual paraphrases checked against exact fictional transcript quotes; no clinical text input, saved approval or patient delivery, so preparing a guide cannot bypass review or healthcare clearance.
- Clinical billing documentation check uses fixed findings tied to exact fictional transcript quotes and never suggests codes, visit levels, or claim submission; prevents AI from implying payment eligibility.
- Clinical reviewed-report PDFs are generated in the browser only from doctor-signed notes (rejected/unsigned refused) and carry fictional-sample and confidentiality labels; prevents AI drafts from looking like approved records.
- Every health route uses HealthAccessGate and owner-emailed decisions; hc_verify_preview_access is service-role-only and atomically binds device and first-entry deadline. Duration changes apply only to unstarted grants; already-started deadlines remain unchanged unless an administrator deliberately extends them. Expiry/exit consumes approval; fresh approval requires a new request. Unused-link redemption expiry remains separate. The gate uses monotonic remaining time, focus/periodic rechecks and cross-tab locks; browser state never extends grants. Watermark identity comes only from the verified current grant or authenticated admin, never token text or visitor lists. Visit logging stays in hc_access_views; admin bypass remains server-verified.
- Delegation Desk shares fixed fictional spoken-request drafts, chart-cited order answers (missing stays unknown) and illustrative standing-rule inbox routing across demo/workspace; sign-off is local rehearsal with no transport, scheduling, prescribing or persistence, so delegation never bypasses physician signature or healthcare clearance.
- AI Elements supplies conversation primitives; disabled attachments and shared icon sizing block hidden uploads.
