# 1325 Clinical rules
- National health exchange preparation is an independent shared private module with a fixed readiness inventory and existing synthetic FHIR evidence; sample counts never become compliance percentages or live clearance, and no real data, credentials, saved readiness decisions or transport are accepted.
- Public clinical photography uses explicit page-owned imports and optional image-bearing feature cards with illustrative captions, keeping placement auditable without changing private workflows.
- Clinical narration is fixed prerecorded explanation or numbered fictional evidence in one gate-scoped player, never a second prompt or agent execution; sound defaults off and gate unmount stops audio to preserve intake and private-session boundaries.
- Clinical server operations require validated Auth plus active email-matched owner approval/device/deadline, or server-verified admin access; data policies use the private checker and clients cannot write patient/chart/billing text. Product questions use a closed browser-local vocabulary and transmit only catalog topic/intent IDs; raw typing, microphone and patient input remain blocked, so warnings cannot substitute for intake restrictions.
- Clinical product conversation uses shared Kayla identity and server-owned documentation with signed user-bound history; gate-scoped memory clears on access/account loss, sends bounded verified context and discards failed turns. No persistence, general chat, specialist execution or clinical tools; opt-in answer speech shares one audio lane with narration.
- Saved note assertions and review findings are exact source excerpts, with AI grouping kept separate from correctness claims; one atomic decision per version prevents conflicting sign/reject outcomes. Typed signer names and team roles are sample attestations, not verified physician licensure.
- Clinical loaders return rows or failure, clear stale content and ignore obsolete requests; guarded mutations confirm saved identifiers before success. Exports validate every statement/flag against verbatim source excerpts; email decisions open a 1325.ai confirmation screen and change state only on a deliberate POST carrying the secret link token, conditional on current status, so scanners cannot decide and phones work.
- Clinical record review uses server-owned fixtures, rejects client record text, validates exact page quotations before saving, and records separate clinic-authorized review decisions; this prevents uploads from bypassing the fictional-only stage and keeps AI completion distinct from physician review.
- The clinical BAA route is a read-only preparation page without signature submission or agreement storage until approved legal documents and vendor coverage exist; this prevents placeholder copy from becoming an executable contract.
- Saved review acceptance rechecks immutable packet identity, literal quotations, assertions and source dates; revision requests remain available for unsupported older drafts. Approval cookies are request/action-scoped and consumed after saved decisions so independent email tabs cannot overwrite one another.
- Clinical AI note-taking (health-kayla-notes) drafts only from server-owned fictional transcripts, cites transcript lines validated server-side, and stores doctor sign-off separately (hc_note_signoffs, one decision per note); live recording stays locked until HIPAA clearance. Clinical edge functions deploy via Supabase CLI with SB_DEPLOY_TOKEN.
- Clinical reviewed-report PDFs are generated in the browser only from doctor-signed notes (rejected/unsigned refused) and carry fictional-sample and confidentiality labels; prevents AI drafts from looking like approved records.
- Every health route uses HealthAccessGate and owner-emailed decisions; hc_verify_preview_access is service-role-only and atomically binds device and first-entry deadline. Duration changes apply only to unstarted grants; already-started deadlines remain unchanged unless an administrator deliberately extends them. Expiry/exit consumes approval; fresh approval requires a new request. Unused-link redemption expiry remains separate. The gate uses monotonic remaining time, focus/periodic rechecks and cross-tab locks; browser state never extends grants. Watermark identity comes only from the verified current grant or authenticated admin, never token text or visitor lists. Visit logging stays in hc_access_views; admin bypass remains server-verified.
- AI Elements supplies conversation primitives; disabled attachments and shared icon sizing block hidden uploads.
- Workspace screen rules live in src/pages/health/workspace/AGENTS.md; read it before changing files there.
