# 1325 Clinical rules
- National health exchange preparation is an independent shared private module with a fixed readiness inventory and existing synthetic FHIR evidence; sample counts never become compliance percentages or live clearance, and no real data, credentials, saved readiness decisions or transport are accepted.
- Public clinical photography uses explicit page-owned imports and optional image-bearing feature cards with illustrative captions, keeping placement auditable without changing private workflows.
- Clinical narration is fixed prerecorded explanation or numbered fictional evidence in one gate-scoped player, never a second prompt or agent execution; sound defaults off and gate unmount stops audio to preserve intake and private-session boundaries.
- Clinical server operations require validated Auth plus active email-matched owner approval/device/deadline, or server-verified admin access; data policies use the private checker and clients cannot write patient/chart/billing text, except the pilot test-patient tables described in src/lib/clinical/AGENTS.md. Product questions use a closed browser-local vocabulary and transmit only catalog topic/intent IDs; raw typing and patient input remain blocked, and the workspace-only Ask Kayla microphone only fills the question box through the shared pilot talk-to-type path (never auto-sends), so warnings cannot substitute for intake restrictions.
- Clinical product conversation uses shared Kayla identity and server-owned documentation with signed user-bound history; gate-scoped memory clears on access/account loss, sends bounded verified context and discards failed turns. No persistence, general chat, specialist execution or clinical tools; opt-in answer speech shares one audio lane with narration. In the clinic workspace, health-kayla-voice speaks answers in Kayla's recorded voice only after verifying the same signed answer receipt plus approval and clinic membership (no free text, nothing stored, words never logged); answers are spoken in sentence-boundary pieces (short first piece, next prepared during playback) so speech starts in seconds, and a voice failure shows a retry message instead of switching to the device voice (device voice only where no signed answer exists, e.g. the public demo), so the voice vendor can never read arbitrary or patient text.
- Saved note assertions and review findings are exact source excerpts, with AI grouping kept separate from correctness claims; one atomic decision per version prevents conflicting sign/reject outcomes. Typed signer names and team roles are sample attestations, not verified physician licensure.
- Clinical loaders return rows or failure, clear stale content and ignore obsolete requests; guarded mutations confirm saved identifiers before success. Exports validate every statement/flag against verbatim source excerpts; email decisions open a 1325.ai confirmation screen and change state only on a deliberate POST carrying the secret link token, conditional on current status, so scanners cannot decide and phones work.
- Clinical record review uses server-owned fixtures, rejects client record text, validates exact page quotations before saving, and records separate clinic-authorized review decisions; this prevents uploads from bypassing the fictional-only stage and keeps AI completion distinct from physician review.
- The clinical BAA route is a read-only preparation page without signature submission or agreement storage until approved legal documents and vendor coverage exist; this prevents placeholder copy from becoming an executable contract.
- Saved review acceptance rechecks immutable packet identity, literal quotations, assertions and source dates; revision requests remain available for unsupported older drafts. Approval cookies are request/action-scoped and consumed after saved decisions so independent email tabs cannot overwrite one another.
- Clinical AI note-taking (health-kayla-notes) drafts only from server-owned fictional transcripts, cites transcript lines validated server-side, and stores doctor sign-off separately (hc_note_signoffs, one decision per note); live recording of visits stays locked until HIPAA clearance (pilot note dictation is the single exception, see src/lib/clinical/AGENTS.md). Clinical edge functions deploy via Supabase CLI with SB_DEPLOY_TOKEN.
- Clinical reviewed-report PDFs are generated in the browser only from doctor-signed notes (rejected/unsigned refused) and carry fictional-sample and confidentiality labels; prevents AI drafts from looking like approved records.
- Every health route uses HealthAccessGate and owner-emailed decisions; hc_verify_preview_access is service-role-only and atomically binds device and first-entry deadline. Duration changes apply only to unstarted grants; already-started deadlines remain unchanged unless an administrator deliberately extends them. Expiry/exit consumes approval; fresh approval requires a new request. Unused-link redemption expiry remains separate. The gate uses monotonic remaining time, focus/periodic rechecks and cross-tab locks; browser state never extends grants. Viewer identity comes only from the verified current grant or authenticated admin, never token text or visitor lists; private screens carry no personal viewer watermark. Visit logging stays in hc_access_views; admin bypass remains server-verified.
- Guest password-free sign-in uses health-access code_send/code_verify: codes go only to the email of the caller's server-verified current grant (hashed, 10 min, single use, 5 tries) and verification returns a one-time Auth link hash, so the browser never chooses the recipient account.
- AI Elements supplies conversation primitives; disabled attachments and shared icon sizing block hidden uploads.
- Workspace screen rules live in src/pages/health/workspace/AGENTS.md; read it before changing files there.
- Pilot (saved test-patient) rules live in src/lib/clinical/AGENTS.md; read it before changing pilot screens.
- Public /health/pilot (and /pilot redirect) files Pilot Doctor requests through the same health-access request path with request_source 'pilot' and a server+trigger-required test-patients-only attestation; the tag only labels emails and the admin list and never skips owner approval or changes viewing limits.
- Each workspace screen element carries its own key prefix (checked by clinical-workspace-unique-screens test); shared keys made React stack stale Daily huddles cards. Kayla's voice reads overlong answers up to the last fitting sentence then points to the screen, and refusals are logged by reason code only.
