# 1325 Clinical pilot library rules
- Pilot Patients (hc_pilot_patients/records/visit_notes/note_addenda/audit; rules in src/lib/clinical/pilot-records.ts and pilot-visit-notes.ts) is the only saved clinical entry: preview-gated clinic members, required made-up test-patient attestation, SSN rejection, append-only records, author-only drafts that lock on signature with addenda-only follow-up, trigger-written activity/chart-opened log readable by owners, masked names and idle screen lock; empty clinics auto-load fixed fictional samples via hc_pilot_seed_samples (is_sample settable only by the loader) and owners may wipe/reload via hc_pilot_reset; labeled HIPAA-style pilot safeguards, never compliance, so real-data go-live remains a distinct attorney-approved step.
- DictationButton + health-pilot-dictation (limits in src/lib/clinical/dictation.ts and the function's rules.ts) is the only clinical microphone path, used by pilot visit-note talk-to-type and workspace-only spoken Ask Kayla questions (purpose 'question', shorter limit): preview-verified clinic members, 16 kHz WAV clips, straight to the BAA-requested OpenAI organization (refuses without its org ID, never Lovable AI), no stored or logged audio/words. Note words append to drafts only and never auto-save or sign; question words only fill the Ask Kayla box and must pass the same local product-only check before topic IDs are sent, so voice never bypasses the real-patient-detail rule.
- Pilot go-live (PilotGoLive + src/lib/clinical/go-live.ts): real patients (hc_pilot_patients.is_real) save only while hc_real_patients_allowed is true — an active admin-recorded hc_go_live_unlocks row (attorney letter, consent version, Lovable ruling, risk assessment, clinic agreement) AND every hc_vendor_baas row cleared, rechecked on every write so tracker downgrades re-lock automatically; admins/owners can lock with a reason, reset refuses clinics with real patients, so no single click or browser state can expose real data.
- Pilot staff roles (src/lib/clinical/pilot-roles.ts mirrors hc_member_role/hc_has_clinic_role/hc_can_read_chart): owner/doctor/nurse read charts; front_desk/biller see demographics and read medical rows only through hc_pilot_break_glass (reasoned, 30 minutes, owner-logged); only owner/doctor prescribe, order labs, cancel labs and sign notes, enforced in RLS and triggers so screen gating never grants access.
- Pilot prescriptions, lab orders and social screenings (PilotOrders.tsx; rules in prescriptions.ts, lab-orders.ts, fairness.ts) are append-only practice entries never transmitted to pharmacies, labs or insurers; the starter interaction list is not a licensed drug database, server allergy matches and any warning require a written override, and the race-free CKD-EPI 2021 eGFR is display-only. Downtime printing is test-patient only until go-live review.
- Real-patient chart (PilotChart when hc_pilot_patients.is_real; rules in src/lib/clinical/real-patient-chart.ts) is writable only while hc_go_live_status reports real_patients_allowed (rechecked each minute and after failed writes), uses the privacy shell's shorter real-patient idle lock, hides talk-to-type, and signs notes only after a fresh password sign-in that the hc_pilot_visit_notes_real_sign trigger verifies from the JWT amr timestamp; records stay append-only except one dated, reasoned medicine stop, so the browser can never edit, delete or sign real data on its own.
- Pilot Phase 2 (PilotSchedule, PilotBilling, PilotPortal, PilotBoost; rules in scheduling.ts, practice-billing.ts, patient-portal.ts, boost-smart.ts): appointments block same-provider overlap and only step booked→checked in→done/discharged/left AMA (discharge and AMA owner/doctor/nurse only, AMA needs a reason) or cancelled/no-show; practice claims attach to one signed visit, never suggest codes and are never transmitted (sent/paid/denied are hand-recorded rehearsal); the patient portal is test-patient only, reached through hc_portal_patient links an approved tester account receives from clinic staff, and shows only that patient's rows and signed notes; BOOST reads the fixed public SMART Health IT sandbox via fhirclient, saves nothing and rejects any other server. All triggers enforce this server-side so screen gating never grants access.
- The admin Outside Approvals Tracker (hc_compliance_milestones, compliance-milestones.ts) records certification, network and audit paperwork only; no status there enables e-prescribing, lab/record exchange, claim sending or real patients.
- Kayla workspace voice (src/lib/clinical/kayla-workspace-voice.ts): the four daily huddles (morning 7 AM, afternoon 1 PM, evening 7 PM, night 11 PM; session name is the only extra input, legacy 'midday' maps to afternoon) speak in Kayla's recorded voice and add counts-only patient updates since the previous huddle (bookings, check-ins, completed/discharged/left-AMA visits, no-shows, cancellations, new/stopped prescriptions, new labs; closed visits are final so updated_at is the close time), with health-kayla-voice building the script itself (shared _shared/clinical-huddle.ts, caller's own RLS, no client text, no names) so the vendor never receives chart words; order read-backs use Kayla's recorded voice only for made-up test patients while hc_real_patients_allowed is false (service rebuilds the sentence from strictly checked order fields plus allergies it reads itself; real patients, a cleared clinic or unusual characters fall back to the device voice), because the voice vendor has no BAA; hands-free 'Kayla, open …' commands only switch screens; Kayla voices the Agentic team by role, never a second voice.
- Pilot patient photos (PilotPatientPhoto + src/lib/clinical/pilot-photos.ts) are display-only: the three fixed samples get bundled computer-generated faces, every other test or real chart shows an initials placeholder, nothing is uploaded or stored, and faces hide with names under the privacy switch, because a face identifies a patient like a name does.
