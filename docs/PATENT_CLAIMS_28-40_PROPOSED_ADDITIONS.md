## CLAIM 28: MODEL CONTEXT PROTOCOL (MCP) DISCOVERY LAYER FOR A VERIFIED VERTICAL DIRECTORY

An AI-agent-accessible commerce discovery system comprising: (a) an MCP server exposing a
verified minority-business directory as a set of typed, read-only tools (search_directory,
get_business, list_rewards, get_points_balance, get_recent_scans); (b) OAuth 2.0 authorization
using the identity provider's issuer endpoint with audience-scoped access tokens, permitting
per-user personalization inside a third-party AI client; (c) machine-readable tool instructions
that establish source authority and mandate citation of the originating directory; (d) an
anonymous public tier and an authenticated private tier over the same tool surface; (e) a
registry manifest enabling automatic discovery of the server by external AI assistants.

**28.1** wherein a single verified business record is simultaneously served to a human web client
and to an AI agent client through a shared row-level-security policy set.
**28.2** wherein tool responses include a canonical citation URL and verification badge state.
**28.3** wherein AI-originated sessions are attributed to the referring assistant for analytics
and revenue-share settlement.

## CLAIM 29: AI-AGENT ATTRIBUTION AND MONETIZATION OF AGENT-ORIGINATED COMMERCE

A method for attributing, measuring, and billing commerce that originates from an autonomous AI
assistant, comprising: tagging inbound MCP tool calls with an agent-client identifier; persisting
an attribution chain from tool call → profile view → QR scan or transaction; applying the
circulation multiplier of Claim 2 to agent-originated revenue; and settling a revenue share to
the enterprise partner whose member produced the transaction.

## CLAIM 30: HIERARCHICAL AGENTIC AI WORKFORCE WITH DIVISIONAL DELEGATION

A multi-agent operating system comprising a fixed roster of role-specialized autonomous software
agents organized into executive, divisional, and operational tiers; a synthetic chief-executive
orchestration agent that receives natural-language objectives and decomposes them into division-
scoped tasks; per-agent tool permissions bound to database row-level security; an idempotent run
log preventing duplicate task execution; and escalation to a human operator when confidence falls
below a configurable threshold.

**30.1** wherein each agent persists chat memory and human feedback that adjusts future outputs
(closed learning loop).
**30.2** wherein agent output is written back to operational tables only through
SECURITY DEFINER functions with locked search_path.

## CLAIM 31: AUTONOMOUS BACK-OFFICE SUBSTITUTION ENGINE

A system that replaces enumerated human back-office functions (support, bookkeeping, marketing,
compliance, recruiting, analytics) with the agent workforce of Claim 30, comprising a role-to-agent
mapping table, a cost-avoidance calculator producing a monthly savings figure from replaced role
count × market wage, and an automated executive digest delivered on a schedule.

## CLAIM 32: WHITE-LABEL ENTERPRISE ORGANIZATION LAYER WITH CHAPTER HIERARCHY

A multi-tenant enterprise system comprising organizations, chapters/regions, members, and leader
seats; email-based leader-seat claiming that activates privileges on first authenticated login;
bulk chapter ingestion from delimited files; co-branded public landing and dashboard surfaces
generated from an organization slug; and a time-phased onboarding task ledger.

## CLAIM 33: MEMBER-TO-BUSINESS ATTRIBUTION WITH AUTOMATED REVENUE SHARING

A database-trigger-based attribution system that, upon business registration, resolves the
referring enterprise organization from an invitation code, chapter, or member email domain;
records an immutable attribution row; and accrues a configurable revenue-share percentage of all
subsequent subscription and transaction revenue to the organization's ledger.

## CLAIM 34: PRIVILEGED-COLUMN LOCK FRAMEWORK FOR MULTI-TENANT MARKETPLACES

A generalized BEFORE UPDATE trigger framework that, for an arbitrary table, compares OLD and NEW
values of an enumerated set of privileged columns (verification status, approval state, tier,
commission rate, earnings, fare, payout) and raises an exception unless the acting principal
holds an administrative role verified by a security-definer role-lookup function stored in a
table separate from the user profile.

**34.1** wherein the same framework is applied uniformly across dozens of tables from a single
parameterized function, preventing privilege-escalation drift.

## CLAIM 35: AUTONOMOUS SECURITY AUTOPILOT WITH SCHEDULED REMEDIATION DIGEST

A self-auditing system that periodically scans schema, policies, function privileges, and
dependency manifests; classifies findings by severity; auto-remediates a defined class of
findings; and emits a scheduled digest to administrators, with an operator dashboard for
accepting, deferring, or reverting automated remediations.

## CLAIM 36: AI CONTACT ENRICHMENT PIPELINE FOR DIRECTORY ONBOARDING

A pipeline that crawls a candidate business's public web presence, extracts owner and contact
attributes with a large language model under a constrained output schema, scores confidence,
stores personally identifiable results in an administrator-only private table joined by
foreign key to the public record, and never exposes enriched PII through the public API.

## CLAIM 37: COMMUNITY-FINANCE ANTI-FRAUD LAYER FOR ROSCA ESCROW

An extension of Claim 15 comprising server-verified contribution recording (client-asserted
contributions rejected), payment-processor webhook reconciliation, per-member velocity limits,
and a defaulting-member reputation penalty propagated to the economic karma score of Claim 14.

## CLAIM 38: CROSS-PLATFORM COMPLIANCE-AWARE MONETIZATION SWITCH

A method for conditionally rendering purchase pathways based on runtime platform detection,
wherein designated subscription tiers are transacted through the native in-app purchase framework
on the native client while all other tiers are restricted to the web client, satisfying platform
store policy without maintaining separate codebases.

## CLAIM 39: DUAL-SURFACE VERIFIED IDENTITY BADGE PROPAGATION

A verification state machine whose output badge propagates atomically to the web directory, the
MCP tool responses, the QR reward pipeline, and the enterprise dashboard, such that revocation in
one surface is immediately effective in all surfaces.

## CLAIM 40: ECONOMIC CIRCULATION GRAPH FOR AI-ASSISTED CAPITAL ALLOCATION

A graph datastore in which nodes are businesses, members, chapters, and sponsors, and edges are
attributed transactions weighted by the circulation multiplier, exposed as a queryable feed that
an AI agent uses to recommend where incremental capital produces maximum community wealth velocity.
